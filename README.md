# django-developer-test-task
Test task for VDK developing company 

Работал - впервые - с deepseek pro via pycharm+Continue. 

Дизайн разработан с помощью figma mcp (continue не поддерживается, поэтому использовал cursor, в будущем думаю сделать адаптер для continue)

## Проблемы при разработке через ИИ:
1. В основном проблемы с плагином в Pycharm - ошибки при парсинге ответа агента, часть размышлений попадает в редактируемые файлы.
2. Claude 5.5 Sonnet без подписки пожирает примерно в сотню раз больше денег при генерации токенов чем deepseek :)
3. Агент без дополнительных инструкций тратит токены на попытки проверить результат - пытается авторизоваться, ищет пользователей, при этом ищет джанго в локали, когда он в докере. 
3.1. Но в целом, большинство проблем конкретно связки Агент\Проект я думаю легко правится с помощью дополнительного контекста. Интересно, сколько это добавляет в цене...

## Содержимое проекта
Авторизация, админка, страница добавления чека, список добавленных чеков. Добавление одинаковых чеков энфорсится с помощью unique_constraint на уровне базы, джанго форма автоматически цепляет это ограничение. 

Все страницы сверстаны под три брейкпоинта (>1200px, <768px и между ними). Мобильная версия адаптирована с пониманием того, что таблицы не работают в плане UI с мобильными экранами. Знаком с концептом mobile-first, но здесь он не использовался (потому что впервые верстал агентом)

Инфраструктура сделана достаточно просто и в то же время эффективно по моим меркам. Статика собирается в staticfiles в корне проекта, media лежит там же. 
Статика, используемая при разработке лежит в папках каждого подприложения.

Весь видимый пользователями текст подготовлен к появлению английского языка (что является для меня стандартом, хоть и не запрошено), но локаль пока не сгенерирована - столкнулся с проблемами, время на решение которых пока не нашёл.
